# Как участвовать в разработке

## Перед началом

1. Выберите свободную Issue и напишите, что берёте её в работу.
2. Обновите `main`: `git pull --rebase origin main`.
3. Создайте ветку: `git switch -c feature/<короткое-название>`.
4. Не добавляйте секреты, `.env`, чужие данные и ассеты оригинальной игры.

## Локальная проверка

```bash
npm install
npm run check
npm test
npm run build
```

Для ручной проверки запустите `npm run dev`, откройте `http://localhost:5173` в двух вкладках, создайте комнату и подключитесь к ней по коду.

## Pull Request

- одна Issue — одна небольшая ветка и один PR;
- используйте коммиты `feat:`, `fix:`, `docs:`, `test:`, `chore:`;
- укажите `Closes #<номер>`, что изменено и как проверить;
- для UI приложите скриншот, для сетевой логики — сценарий из двух клиентов;
- перед ревью выполните `npm run check && npm test && npm run build`;
- изменение `shared/` или Socket.IO-событий требует ревью Team Lead и Backend/Realtime;
- не включайте в PR форматирование или рефакторинг вне задачи.

`main` должен всегда собираться. До включения защиты ветки прямой push допустим только Team Lead для первоначального каркаса и срочного восстановления сборки.
